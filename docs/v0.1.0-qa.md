# v0.1.0 QA 验收清单

> 说明：本文是 v0.1.0 测试版就绪的 QA 验收计划与当前验证记录。除“当前验证记录”中列出的命令和 Podman 集成验证外，其他集成、手工接入、原生 Docker 项均为待执行验收项，不是已执行结果。

## 测试结论与风险等级

- 当前建议：**有条件进入 v0.1.0 测试版候选**。
- 风险等级：**中**。
- 主要原因：代码级验证、Podman Compose 栈、当前代码临时二进制 `/health`、Prowlarr 真实搜索、Sonarr/Radarr 通过 jproxy-go 接入 Prowlarr 已完成；Jackett 路由可返回 HTTP 200 但当前 Jackett 无已配置 indexer，尚不能证明 Jackett 端到端有结果搜索；原生 Docker build/run 仍未完成。
- 迁移口径：v0.1.0 只验收 Core Proxy MVP 范围；Radarr-only Phase 1 静态标题格式化是默认关闭的可选能力；完整规则格式化、标题库/别名库、SQLite/Java DB、Web 管理、登录/JWT、下载器集成不纳入本版本通过标准。

## 手工接入步骤

### 1. 准备上游

1. 启动 Jackett，确认原始 Torznab URL 可访问。
2. 启动 Prowlarr，确认原始 API/search URL 可访问。
3. 记录 Jackett/Prowlarr 的 base URL 和 API key。

### 2. 本地运行 jproxy-go

Windows CMD 示例：

```bat
set ADDR=:8117
set JACKETT_URL=http://127.0.0.1:9117
set PROWLARR_URL=http://127.0.0.1:9696
set MIN_COUNT=6
set INDEXER_RESULT_CACHE_EXPIRES=15
set CACHE_EXPIRES=4320
set HTTP_TIMEOUT_SECONDS=60
go run ./cmd/jproxy
```

健康检查：

```text
http://127.0.0.1:8117/health
```

期望：HTTP 200，body 为 `ok`。

### 3. 直接请求代理 URL

Jackett for Sonarr：

```text
http://127.0.0.1:8117/sonarr/jackett/api/v2.0/indexers/all/results/torznab?apikey=<key>&t=search&q=<keyword>&cat=5000&limit=100&offset=0
```

Prowlarr for Sonarr：

```text
http://127.0.0.1:8117/sonarr/prowlarr/api/v1/search?apikey=<key>&t=search&q=<keyword>&cat=5000&limit=100&offset=0
```

Jackett for Radarr：

```text
http://127.0.0.1:8117/radarr/jackett/api/v2.0/indexers/all/results/torznab?apikey=<key>&t=search&q=<movie>&cat=2000&limit=100&offset=0
```

Prowlarr for Radarr：

```text
http://127.0.0.1:8117/radarr/prowlarr/api/v1/search?apikey=<key>&t=search&q=<movie>&cat=2000&limit=100&offset=0
```

验收：返回 XML，包含 `<rss>`/`<channel>`；有结果时包含 `<item>`；上游参数与原始 Jackett/Prowlarr 搜索一致。

### 4. Sonarr/Radarr UI 接入

1. 在 Sonarr/Radarr 添加 Torznab/Custom indexer。
2. 保留原 Jackett/Prowlarr API key 与 query 参数。
3. 仅将 base URL 替换为 jproxy-go 对应前缀：
   - Sonarr + Jackett：`http://<host>:8117/sonarr/jackett/api/v2.0/indexers/all/results/torznab`
   - Sonarr + Prowlarr：`http://<host>:8117/sonarr/prowlarr/...`
   - Radarr + Jackett：`http://<host>:8117/radarr/jackett/api/v2.0/indexers/all/results/torznab`
   - Radarr + Prowlarr：`http://<host>:8117/radarr/prowlarr/...`
4. 点击 Test，随后执行一次实际搜索。

验收：Sonarr/Radarr 测试通过；实际搜索返回结果；jproxy-go 不崩溃；日志/上游请求符合预期。

### 5. Docker 待验证步骤

## 原版 jproxy 对照点

| 对照点 | 原版位置 | Go 版对齐点 | v0.1.0 结论 |
|---|---|---|---|
| Filter 路径 | `Common.FILTER_SONARR_JACKETT_PATH` 等：`/sonarr/jackett/*`、`/sonarr/prowlarr/*`、`/radarr/jackett/*`、`/radarr/prowlarr/*` | `internal/proxy/server.go` 注册相同四类前缀 | MVP 范围应保持一致 |
| 上游路径拼接 | `*ServiceImpl.getIndexerUrl` 使用 Jackett/Prowlarr base URL，并用 `/(sonarr|radarr)/jackett|prowlarr` 去前缀 | `upstreamURL` 去除相同 jproxy 前缀并拼接 `JACKETT_URL/PROWLARR_URL` | MVP 范围应保持一致 |
| Query 处理 | `executeNewRequest` 将请求 query 带到上游 | Go 版 clone query 后 `q.Encode()` 请求上游 | 需真实上游确认特殊字符编码 |
| 结果缓存 key | 原版 `generateCacheKey` 需忽略 apikey；Filter 先读 `indexerResultCache` | Go 版 `makeCacheKey` 去除 `apikey` | 单测已覆盖不同 apikey 命中缓存；需集成确认 |
| 结果缓存 TTL | 原版 `time.indexer-result-cache-expires`，分钟 | Go 版 `INDEXER_RESULT_CACHE_EXPIRES`，默认 15 分钟 | 需 TTL 手工验证 |
| 结果缓存容量 | 原版 Caffeine 有容量边界 | Go 版 `RESULT_CACHE_MAX_ENTRIES`，默认 1000 | 单测覆盖容量淘汰；配置文档已同步 |
| offset 缓存 | 原版 `INDEXER_SEARCH_OFFSET`，`getOffsetList` 初始化 0 列表 | Go 版 `offsetCache` 初始化 `[]int` | 单测覆盖边界；Prowlarr offset 对照已验证双方均 0 item |
| offset 缓存容量 | 原版 Caffeine 有容量边界 | Go 版 `OFFSET_CACHE_MAX_ENTRIES`，默认 1000 | 单测覆盖容量配置；配置文档已同步 |
| offset 当前索引 | 原版 `calculateCurrentIndex` 对边界使用 `>=` | Go 版同样 `v >= offset` | 单测已覆盖边界行为 |
| Prowlarr 分页异常 | 原版 count 超 limit 时裁剪 XML | Go 版 count 超 limit 时 `trimXML` | 单测覆盖；Prowlarr 436 item 结果经 `limit=10/1` 实测裁剪正确 |
| XML 合并 | 原版 `XmlUtil.merger` | Go 版 `mergeXML` | 单测覆盖；复杂 XML 需样例确认 |
| 格式化规则 | 原版会执行 `executeFormatRule`，完整规则由具体服务扩展 | Go 版默认关闭；已提供 Radarr-only Phase 1 静态 XML 标题格式化 MVP，完整规则引擎、Sonarr、同步和数据库仍不包含 | 是 v0.1.0 已知范围差异/限制 |
| 标题库/别名库 | 原版接 SQLite/服务查询标题、别名 | Go 版只实现基础搜索词扩展 | 是 v0.1.0 已知范围差异/限制 |
| 配置来源 | 原版 DB/system config + application 配置 | Go 版环境变量 | 是 v0.1.0 已知部署差异 |
| 健康检查 | 原版非本 MVP 核心对照点 | Go 版 `/health` | v0.1.0 新增运行验收点 |

  1. 代码级门禁通过：`go test ./...`、`go build ./cmd/jproxy`；建议 `go vet ./...` 通过。
