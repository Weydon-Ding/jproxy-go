# v0.1.0 排期计划

## 版本定位

`v0.1.0` 建议定位为：

```text
Core Proxy MVP
```

目标是发布第一个外部可部署、可真实接入测试的基础代理版本。

该版本重点验证 Go 版迁移路线、基础代理链路、缓存、XML 合并/裁剪、配置和 Docker 部署能力。

## 推荐周期

```text
约 2 周 / 10 个工作日
```

## v0.1.0 范围

迁移口径：v0.1.0 仅承诺核心代理 MVP 范围内的原版行为对齐；规则格式化、标题库/别名库、SQLite/Java DB、Web 管理等仍按“明确不包含”处理，不因“默认保持原版行为”扩大本版本范围。

### 必须包含

- 核心 Jackett/Prowlarr 代理。
- Sonarr/Radarr 路由。
- 基础搜索扩展。
- XML 合并、计数与裁剪。
- 结果缓存。
- offset 分页缓存。
- 基础配置能力。
- 健康检查。
- Docker 构建与运行。
- README 部署说明。
- release note。

### 明确不包含

- 完整规则格式化引擎。
- 标题库 / 别名库。
- SQLite 存储。
- Java DB 完整兼容。
- Web 管理后台。
- 登录 / JWT。
- Downloader 集成。
- 多用户、多实例管理能力。

## 推荐版本路线

```text
v0.1.0 = Core Proxy MVP
v0.2.0 = Rule Formatting
v0.3.0 = Title Library / Alias / SQLite
v0.4.0+ = Admin API/UI、登录、下载器集成等
```

## 验收标准

### 代码级验收

必须通过：

```bat
go test ./...
go build ./cmd/jproxy
```

建议通过：

```bat
go vet ./...
golangci-lint run
```

注意：`go test ./...` 通过但没有测试文件时，不能视为质量充分。

### 功能验收

迁移验收要求：以下核心代理 MVP 行为必须对照原版 `../jproxy` 相关实现确认；默认保持原版行为，若有意差异必须在 README/release note/测试中写明。

- Sonarr/Radarr 路由能正确转发到 Jackett/Prowlarr。
- Query 参数完整透传。
- 上游异常时返回合理错误，不导致进程崩溃。
- 多次搜索结果可合并为可用 XML。
- `limit` / `offset` 场景行为正确。
- 缓存 TTL 生效。
- `/health` 返回 `ok`。

### Docker 验收

示例命令：

```bat
docker build -t jproxy-go:v0.1.0 -f deployments/docker/Dockerfile .
```

运行后访问：

```text
http://127.0.0.1:8117/health
```

期望返回：

```text
ok
```

### 发布验收

- `release/v0.1.0` 分支创建。
- README 更新。
- Docker 构建通过。
- 本地二进制构建通过。
- 至少一组 Jackett 或 Prowlarr 实测通过。
- 至少一组 Sonarr 或 Radarr 接入测试通过。
- 已知限制写入 release note。
- `main` 打 tag：`v0.1.0`。
- `main` 合并回 `dev`。

## 主要风险

| 风险 | 影响 | 应对 |
|---|---|---|
| 当前测试覆盖不足 | 发布质量不可控 | 优先补 M1 测试 |
| 规则格式化范围过大 | 拖慢 v0.1.0 | 推迟到 v0.2.0 |
| XML 字符串处理较朴素 | 兼容性风险 | 用典型 Jackett/Prowlarr XML 样例覆盖 |
| Java 版行为兼容性不确定 | 用户预期偏差 | v0.1.0 核心代理 MVP 行为逐项对照原版 `../jproxy`；已知差异写入 release note |
| Docker 访问宿主机服务差异 | 部署踩坑 | README 区分 Windows/macOS/Linux 说明 |
